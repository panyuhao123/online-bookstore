# UI 与交互优化说明（对标当当网图书电商 APP）

> 适用章节：毕业论文「系统实现 / 界面设计」或「系统优化」小节，以及答辩 PPT 的 UI 部分。
> 原则：**借鉴信息层级、导航逻辑、文案规范与交互反馈；不复制配色、图标与图片素材。**

## 一、对标方法与边界

以成熟图书电商 APP（当当网）为参照，对本项目的移动端界面做了一次逐项比对。参照对象是**信息架构与交互范式**，不是视觉素材：

| 类别 | 处理方式 | 说明 |
| --- | --- | --- |
| 页面信息层级 | ✅ 借鉴 | 个人中心「身份区 → 订单入口 → 资产 → 工具入口 → 内容推荐」的分层方式 |
| 导航结构 | ✅ 借鉴 | 底部 Tab 保持「首页 / 分类 / 当读 / 购物车 / 我的」五个入口 |
| 组件布局 | ✅ 借鉴 | 订单快捷入口单行排布、结算栏「全选 + 合计 + 去结算」三段式 |
| 文案规范 | ✅ 借鉴 | 用户视角命名（待发货 / 待收货），不使用数据库状态名 |
| 交互反馈 | ✅ 借鉴 | 加购成功提示、删除二次确认 |
| 配色 / 图标 / 图片 | ❌ 不复制 | 沿用本项目朱砂红 `#C8362F` 设计 Token，图标为自绘 CSS 线性图形 |
| 悬浮客服按钮 | ❌ 不照搬 | 当当右下角悬浮按钮易遮挡内容，本项目不采用 |
| 首页营销板块堆砌 | ❌ 不照搬 | 本项目首页仅保留 3 个图书楼层，避免信息过载 |

## 二、优化落地对照表

| 原有问题 | 优化方案 | 落地位置 |
| --- | --- | --- |
| 功能入口只用单字（榜 / 类 / 服），表意模糊 | 改为「图形图标 + 完整中文名称」；图标由 CSS 绘制，不引入切图 | `components/entry-icon.vue`、`components/entry-grid.vue`、`pages/index/index.vue`、`pages/mine/mine.vue` |
| 个人中心两套订单模块（顶部统计 + 下方订单） | 订单信息只保留一组快捷入口，顶部资产行只放购物车与评价 | `pages/mine/mine.vue` |
| 订单状态滥用小红点，误导用户 | 移除订单状态红点，数量本身即提示；红点仅保留给购物车角标 | `pages/mine/mine.vue` |
| 购物车结算数字重复（`合计 ¥56(2件)` + `去结算(2)`） | 件数只在合计行出现一次，按钮只写「去结算」 | `pages/cart/cart.vue` |
| 分类侧边栏选中态不明显 | 选中项加「弱红底 + 左侧品牌色竖条 + 加粗」三重信号 | `pages/category/category.vue` |
| 图书卡片信息单薄 | 增加评分（星标 + 分值 + 评价数）、促销标签（仅剩 N 件 / 热销）、作者·出版社、单行简介 | `components/book-card.vue` |
| 文案不规范：「抢首评」「服务器」 | 改为「暂无评价，购买后可发表第一条评价」；调试入口下沉为「服务器地址设置」，主入口改为「客服中心」 | `pages/book/detail.vue`、`pages/mine/mine.vue`、`common/request.js` |
| 订单状态沿用数据库命名（已支付 / 已发货） | 统一为用户视角命名：待支付 / 待发货 / 待收货 / 已完成 | `pages/mine/mine.vue`、`pages/order/list.vue` |
| 存在真实电商不会有的入口：服务器地址设置、客服中心 | 服务器地址改为**隐藏调试入口**（连点头像 5 次，沿用 Android 开发者选项的做法）；客服中心直接移除 | `pages/mine/mine.vue`、`pages/index/index.vue`、`pages.json` |
| 首页宫格堆了需登录的个人入口（我的订单 / 评价 / 地址） | 首页宫格只保留「逛」的四类入口（分类 / 书单 / 新书 / 低价），个人入口收敛到个人中心 | `pages/index/index.vue` |
| 底部 Tab「当读」是自造品牌词，答辩不易理解 | 改为通用词「书单」，Tab、榜单页标题、宫格入口与首页楼层名同步 | `components/tab-bar.vue`、`pages/book/list.vue`、`pages/index/index.vue`、`pages/mine/mine.vue` |

### 关于「客服中心」的取舍判断

**结论：不做。** 真实电商的客服是工单 / 会话系统，需要后端数据支撑；本项目没有这块数据，只能弹一段硬编码文案。这类"空壳入口"与本项目「页面每处数字都来自真实接口」的质量标准相冲突，答辩时被点开反而容易被质疑。售后诉求（查进度、处理发货）已由「我的订单」承接，因此不设客服入口。

### 关于「服务器地址设置」的处理

**不删除页面，只移除可见入口。** 原因是真机联调的实际约束：手机要访问电脑的局域网 IP，而 IP 会随 WiFi 重连被 DHCP 重新分配；启动时的自动探测只试「上次成功的地址 + 打包时写死的默认地址」两个候选，不扫描网段，两者同时失效时手动改地址是唯一兜底。因此改为连点头像 5 次的隐藏入口，页面标题改为「调试设置」并在页内注明「仅供开发调试，不属于应用功能」。

## 三、核查后确认「本就已具备」的能力

比对过程中逐条核验，以下能力此前已实现，本次无需改动（避免重复建设）：

1. **底部 Tab 为图标 + 完整中文**：自绘 `components/tab-bar.vue`，五个入口（首页 / 分类 / 当读 / 购物车 / 我的），图标与文字同步变色，购物车带实时角标。
2. **加购成功 Toast**：`common/cart-action.js` 统一处理（已登录提示「已加入购物车」，未登录提示「已加入本机购物车，登录后自动同步」）。
3. **删除二次确认**：`pages/cart/cart.vue` 使用 `uni.showModal` 确认后再移除。
4. **无悬浮遮挡层**：全站没有浮动客服按钮，不存在当当那种悬浮按钮遮挡内容的问题。
5. **首页模块克制**：仅「新书上架 / 当读热销 / 低价优选」三个楼层，未堆砌营销板块。

## 六、答辩可直接引用的表述

> 在界面设计阶段，我以当当网等成熟图书电商 APP 作为参照对象，对其信息层级、导航逻辑与文案规范进行了拆解比对。借鉴之处在于：将个人中心重复的订单统计模块精简为一组订单快捷入口；把单字功能入口改为「图形图标 + 完整中文名称」的形式，消除表意歧义；补齐加购成功提示、删除二次确认等交互反馈；统一订单状态的用户视角命名；并强化分类页的选中态标识。同时做了一轮功能真实性收敛：移除没有数据支撑的客服入口，把服务器地址这类开发调试项改为隐藏入口，首页只保留与「逛」相关的入口，个人入口一律收敛到个人中心。在边界上明确：只参照布局与交互逻辑，不复制任何配色、图标与图片素材，界面沿用本项目自有的朱砂红设计 Token，功能图标为自行绘制的 CSS 线性图形。此外也规避了参照产品中的已知问题，例如未采用右下角悬浮客服按钮，首页图书楼层控制在三个以内以避免信息过载。
