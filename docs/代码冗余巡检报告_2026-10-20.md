# 代码冗余巡检报告

**项目**：线上书店（图书电商系统）
**技术栈**：SpringBoot 3.2.5 + MyBatis-Plus 3.5.7 + Vue3(Element Plus) + uni-app
**巡检日期**：2026-10-20
**巡检范围**：`bookstore-server` / `bookstore-admin` / `bookstore-web` / `bookstore-app` 四端源码 + 仓库级产物
**巡检方式**：全量符号引用计数（类 / 方法 / 常量 / 导出函数 / 组件 / 路由 / 端点）+ 人工逐项复核，**未修改任何代码**
**明确排除**：缓存事务三层包装、BCrypt/MD5 密码兼容、订单库存扣减核心、`entity/` 实体、`Controller` 活跃端点

## 一、结论摘要

| 指标 | 结果 |

**总体判断**：本项目代码整洁度高于同类毕设项目的平均水平。**没有发现"注释掉的整段死代码"**（73 处多行注释全部为设计说明 Javadoc，无一是被注释掉的实现），**没有 `System.out` / `printStackTrace` / `TODO` / `FIXME` / `@Deprecated` 残留**，错误码与订单状态枚举 100% 被引用，Mapper 无孤立自定义方法，20 个 APP 页面全部在 `pages.json` 注册，12 个管理端视图全部在路由中，**后端 0 个孤儿接口**（唯一无调用方的 `/ready` 是运维就绪探针，属预期保留）。

因此本次巡检的实际价值集中在**"过度导出的函数"与"跨页面复制的私有工具函数"**两类低风险冗余，而非大块废弃代码。

### D-04 订单状态文案存在"双来源"

`bookstore-web/src/utils/format.js:15` 定义 `ORDER_STATUS_TEXT` 本地映射；而后端 `OrderVO:97` 已通过 `OrderStatus.textOf()` 返回 `statusText`。
`bookstore-web/src/utils/excel.js:57` 写的是 `order.statusText || orderStatusText(order.status)` —— **两套来源并存，用 `||` 兜底**。

**风险判断**：低但真实——若后端新增状态而前端映射未同步，列表页显示后端新文案、订单详情页显示"未知"。
**建议**：**保留兜底**（后端字段缺失时前端仍可渲染），但把 `orderStatusText` 的注释改为"仅兜底，正常路径用 statusText"，避免后来者以为前端映射是权威源。

### D-05 跨端同名工具（结构性重复，不建议合并）

`cart-action.js` / `buy-now.js` / `request.js` / `format.js` 在 `bookstore-web` 与 `bookstore-app` 各有一份。

**判断**：**这是合理的**。两端运行时不同（axios vs `uni.request`）、导航 API 不同（`vue-router` vs `uni.navigateTo`）、存储不同（`localStorage` vs `uni.setStorageSync`），强行抽公共包反而增加构建复杂度。**仅建议在两端文件头互相注明"对端同名文件"**，降低改一端忘另一端的概率。
