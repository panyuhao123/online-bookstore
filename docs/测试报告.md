## 1. 测试目的与范围

验证系统是否达成需求规格中定义的功能与质量目标，重点覆盖：

1. 用户端核心链路：登录 → 浏览/搜索 → 购物车 → 下单 → 支付 → 收货 → 评价；
2. 管理端核心能力：图书/分类/订单/用户/评价管理与操作日志；
3. 非功能属性：鉴权与越权防护、参数校验与异常处理、缓存与降级、定时任务幂等、接口文档完整性。

### 4.4 会话可吊销（38 项）

| 分组 | 关键用例 |
| --- | --- |
| 令牌签发 | 登录返回的 JWT 载荷含唯一 `jti`；同一账号两次登录 `jti` 不同；令牌携带 `exp`（无永久令牌） |
| 吊销生效 | 退出登录后，原令牌访问 `/api/user/info`、`/api/cart/list` 等受保护接口均返回 401「登录状态已失效，请重新登录」 |
| 跨端域隔离 | 用户令牌被吊销不影响管理员令牌，反之亦然；黑名单值分别为 `user:<id>` / `admin:<id>` |
| 幂等与鲁棒 | 同一枚令牌连续登出两次均返回成功（登出路径不参与吊销校验）；撤销不存在的令牌不报错 |
| 公网浏览不受影响 | 不带令牌访问 `/api/book/hot` 等公开接口返回 200 |
| 有效期收敛 | 黑名单键 TTL ≈ 令牌剩余有效期（实测 86398/86399 秒）；重新登录签发新令牌可用，旧令牌不复活 |

## 5. 专项测试

### 5.1 缓存收益（前次实测，方法学已固化）

图书详情接口：冷调用 5.5~6.0 ms → 热调用 3.5~3.9 ms，**耗时降低约 36%**。分类列表提升约 0.8%（数据量小、本就约 1 ms）。

方法学：多次采样取最小值；冷调用前显式删除缓存键强制回源。**不使用"首次调用 vs 中位数"对比** —— 那测到的是 JIT 预热而非缓存收益。

### 5.2 缓存降级

`verify_cache_degrade.py` 通过注入 Redis 故障验证熔断与降级：Redis 不可用时接口仍可正常返回（数据正确），不阻断主流程。该脚本执行时会操作 Redis 进程，本次未重跑以避免中断演示环境，结果引用前次执行记录（通过）。

### 5.3 生产化升级专项验证（2026-10-19）

| 专项 | 手段 | 实测证据 |
| --- | --- | --- |
| 配置快速失败 | `prod` profile 不提供 `JWT_SECRET` 启动 | 启动失败并输出 `配置校验失败：bookstore.jwt.secret 未配置…`；确认 profile 已切到 `prod` |
| 文档环境开关 | `prod` 下探测文档路径 | `/doc.html`、`/webjars/**`、`/v3/api-docs` 均返回 401；`local` 下正常（`/v3/api-docs` 出 openapi 3.0.1） |
| 密码惰性迁移 | 把演示账号重置为 seed 的 MD5 后登录 | 库中密文变为 `$2a$10$…`（60 字符）、`salt` 为空；错误密码不改写密文 |
| 登录锁定 | 连续错误登录至阈值 | 计数键 TTL 1800s、锁定键 TTL 900s；锁定期内正确密码也被拒并提示「请 15 分钟后重试」 |
| 会话吊销 | 登出后用原令牌访问受保护接口 | 401「登录状态已失效，请重新登录」；黑名单键 TTL ≈ 86398s；设备 A 登出不影响设备 B |
| 降级不放大故障 | Redis 不可用时校验黑名单 | 降级放行 + 本地内存兜底 + 一次性告警，60 秒后自动重试恢复 |

1. 需求规格中定义的全部功能需求均已实现并通过验证，**267 项接口/端到端断言全部通过，失败 0 项**；单元测试 **86 项全部通过**，两者合计 **353 项断言全绿**。
