## 2. 部署步骤

### 2.1 初始化数据库

```bash
# 创建库
mysql -u root -p -e "CREATE DATABASE IF NOT EXISTS bookstore DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;"

# 依次执行（口令请用 --defaults-extra-file 传入，避免在命令行暴露）
mysql --defaults-extra-file=<配置文件> < db/schema.sql
mysql --defaults-extra-file=<配置文件> < db/migration_v2_2026-10-16.sql
mysql --defaults-extra-file=<配置文件> < db/migration_v3_operation_log.sql
mysql --defaults-extra-file=<配置文件> < db/migration_v4_review.sql
mysql --defaults-extra-file=<配置文件> < db/seed.sql
```

> 配置文件形如：
> ```
> [client]
> user=root
> password=<实际口令>
> ```
> 用完立即删除。

### 2.2 后端配置与启动

- 后端默认激活 `local` 配置：`bookstore-server/src/main/resources/application-local.yml`（含数据库口令，已被 gitignore，不入库）。
- **首次从代码库拉取后**，该文件不存在，需先由模板生成并填好本机真实值：

```bash
cd bookstore-server/src/main/resources
cp application-local.yml.example application-local.yml   # Windows: copy 亦可
# 然后把里面的 <...> 占位值逐个替换：数据库账号口令、JWT 密钥（>= 32 位随机串）等
```

  > 缺少 `bookstore.jwt.secret` 或密钥不足 32 位时，后端会**拒绝启动并打印明确提示** ——
  > 这是刻意设计的快速失败，避免带着可预测的默认密钥对外提供服务。
  > 生成随机密钥：`openssl rand -base64 48`。

- 生产环境请改用 `SPRING_PROFILES_ACTIVE=prod`，并把口令、密钥等通过环境变量注入
  （参见根目录 `.env.example`）；`prod` 会自动关闭 SQL 日志与 `/doc.html` 接口文档入口。
- 切换对象存储：`STORAGE_TYPE=minio`（默认 `local`）。
- 启动：

```bash
cd bookstore-server
mvn -Dfile.encoding=UTF-8 spring-boot:run
```

- 自检：访问 `http://127.0.0.1:8080/api/category/list` 应返回 `code=200` 且带分类数据。
  **不要用 `/health` 判断数据库连通性** —— 它不查库，数据库挂了也会返回 200。

### 2.3 启动依赖组件

```bash
# Redis（默认 6379）
D:\redis5\redis-server.exe

# MinIO（可选，默认走本地磁盘存储）
D:\minio\minio.exe server D:\minio\data --console-address ":9001"
```

两者未设为开机自启，演示前需手动拉起。

### 2.3.1 登录失败锁定（运维小抄）

连续登录失败达阈值（默认 5 次）后账号会被临时锁定（默认 15 分钟），
锁定期内**即使密码正确也会被拒绝**。相关状态存在 Redis 中：

| 键 | 含义 |
| --- | --- |
| `bookstore:login:fail:user:<手机号>` | APP 用户失败计数（窗口 30 分钟，固定窗口） |
| `bookstore:login:lock:user:<手机号>` | APP 用户锁定标记，TTL 即剩余锁定时间 |
| `bookstore:login:fail:admin:<账号名>` | 管理员失败计数 |
| `bookstore:login:lock:admin:<账号名>` | 管理员锁定标记 |

```bash
# 查看某账号是否被锁（-2 表示无锁定）
D:\redis5\redis-cli.exe ttl bookstore:login:lock:user:13800138000

# 手动解锁单个账号（管理员应急，也可只删 lock 键保留计数）
D:\redis5\redis-cli.exe del bookstore:login:lock:user:13800138000
D:\redis5\redis-cli.exe del bookstore:login:fail:user:13800138000

# 清空所有登录锁定状态
D:\redis5\redis-cli.exe --scan --pattern "bookstore:login:*" | xargs -n1 D:\redis5\redis-cli.exe del
```

应急出口：若管理员账号被锁且无法等待，可临时用 `LOGIN_GUARD_ENABLED=false` 重启服务恢复登录
（该开关同时会在启动日志中打一条安全告警，用后请记得改回）。

### 2.3.2 令牌吊销（退出登录真正生效）

无状态 JWT 的「退出登录」原本只在客户端删掉令牌，服务端仍会认可这枚令牌直到它过期 ——
令牌一旦被复制走（抓包、共享设备、日志泄露），谁拿到都能继续用。
现在退出登录会把令牌的唯一编号（`jti`）写入 Redis 黑名单，该令牌**立即失效**。

| 键 | 含义 |
| --- | --- |
| `bookstore:token:revoked:<jti>` | 已吊销的令牌；值为吊销主体（`user:1001` / `admin:1`），仅供排查 |

键的 TTL 等于令牌的剩余有效期，到期自动消失，不会在 Redis 里越积越多。

```bash
# 查看当前被吊销的令牌
D:\redis5\redis-cli.exe --scan --pattern "bookstore:token:revoked:*"

# 让某枚令牌「复活」（正常演示不需要，仅排查用）
D:\redis5\redis-cli.exe del bookstore:token:revoked:<jti>
```

两个相关配置（都有安全默认值，通常不必改）：

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `JWT_EXPIRE_HOURS` | 24（生产 12） | 令牌有效期。JWT 过期前无法远程作废，有效期越长风险窗口越大 |
| `JWT_REVOCATION_ENABLED` | true | 令牌吊销总开关。设为 false 可回到「登出仅客户端生效」的旧行为（启动日志会打安全告警） |

应急出口：万一吊销逻辑异常导致正常用户被大面积拒绝，用 `JWT_REVOCATION_ENABLED=false` 重启即可。
Redis 本身故障时**不影响业务**：吊销自动降级为「仅本实例内存生效」并打告警，业务接口照常可用。

演示要点：退出登录后，用刚才那枚令牌再调接口会返回 401「登录状态已失效，请重新登录」；
重新登录拿到的新令牌正常可用 —— 说明吊销是**按令牌**而不是按用户生效的，
一台设备登出不会把其他设备一起踢下线。一键验证脚本：`tools/verify_token_revoke.py`。

### 2.4 管理端

cd bookstore-admin

### 2.5 APP 运行与打包

- 运行到手机：HBuilderX 打开 `bookstore-app` → 运行 → 运行到手机或模拟器。
- 打包 APK（**前置条件**：`manifest.json` 的 `appid` 不能为空。若为空，云打包不会被受理，
  命令行会提示"未配置 appid"并长时间无进展）。获取方式：HBuilderX 登录 DCloud 账号后，
  打开 `manifest.json` 的基础配置页面，点击"重新获取"应用标识。
- 打包方式一（推荐）：HBuilderX → 发行 → 原生 App 云打包。
- 打包方式二（命令行，需 HBuilderX 已登录且项目已导入）：

```bash
D:\HBuilderX\cli.exe pack --project D:\workbuddy123\线上书店\bookstore-app \
  --platform android --android.packagename cn.edu.bookstore --android.androidpacktype 1
```

- 真机联调：电脑与手机同一局域网，APP 内置自动探测后端地址；若探测失败，在「我的 → 服务器地址」手动填写电脑的局域网 IP（端口 8080）。

## 4. 功能操作指南

### 4.1 APP 端

| 场景 | 操作路径 |
| --- | --- |
| 注册登录 | 我的 → 登录/注册；未登录访问需登录的页面会自动跳转 |
| 找书 | 首页楼层浏览 / 顶部搜索框输入书名或作者 / 分类页按类目筛选 |
| 排序筛选 | 图书列表页顶部切换综合、销量、价格升降序 |
| 加入购物车 | 详情页「加入购物车」（未登录存本机，登录后自动合并） |
| 结算下单 | 购物车勾选商品 → 结算 → 选择/新增收货地址 → 提交订单 |
| 支付 | 订单详情点击支付（模拟支付，状态变更为已支付） |
| 收货与评价 | 已发货订单点「确认收货」→ 完成后在订单或图书详情发表评分与文字评价 |
| 地址管理 | 我的 → 收货地址，支持新增、编辑、删除、设为默认 |
| 切换后端 | 我的 → 服务器地址，支持自动探测与手动填写 |

### 4.2 管理端

| 场景 | 操作路径 |
| --- | --- |
| 图书维护 | 图书管理 → 新增/编辑（上传封面）、上下架、删除；书名+作者重复会被拒绝 |
| 分类维护 | 分类管理；分类下仍有图书时不允许删除 |
| 订单处理 | 订单管理 → 查看详情 → 发货；超时未支付订单可批量关闭 |
| 用户管理 | 用户管理 → 启用/禁用 |
| 评价管理 | 评价管理 → 按关键词/星级/状态筛选 → 隐藏或恢复；删除仅用于清理垃圾数据 |
| 经营统计 | 首页总览查看核心指标与销售趋势 |
| 系统设置 | 运行时切换后端地址 |

## 5. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 后端启动报 "Failed to obtain JDBC Connection" | 连接串中 `characterEncoding` 必须是 `utf8`，写成 `utf8mb4` 会被 Connector/J 8 拒绝并伪装成连接失败 |
| 自定义环境变量不生效 | 环境变量需加 `BOOKSTORE_` 前缀，避免与 Spring 宽松绑定冲突 |
| `curl` 访问本机接口超时 | 本机存在 HTTP 代理，需加 `--noproxy '*'` |
| 手机访问不到后端 | 使用电脑局域网 IP（`ipconfig` 的 WLAN 地址，排除 VMware 虚拟网卡）；IP 变化后重新探测或手动配置 |
| Android 9+ 网络请求失败 | manifest 已配置 `usesCleartextTraffic: true`，若自行修改请保持开启 |
| Redis 未启动导致接口变慢或报错 | 缓存层已做熔断降级，但演示前建议拉起 Redis 以展示缓存效果 |
| 登录提示「失败次数过多，账号已被临时锁定」 | 触发了登录失败锁定（默认 5 次 / 锁 15 分钟）。等待自动解锁，或按 2.3.1 用 redis-cli 删除锁定键；确实忘了口令时请改用正确口令，锁定期内正确答案也会被拒 |
| 演示时反复输错导致账号被锁 | 脚本 `tools/verify_login_lockout.py` 也会故意触发真实锁定，运行结束会自动清理；若中途中断，按 2.3.1 手动删除 `bookstore:login:*` 即可 |
| 上传图片失败（MinIO 模式） | 确认 MinIO 已启动且 `STORAGE_TYPE=minio` 与 endpoint 配置一致；默认 local 模式不依赖 MinIO |
| 评价列表为空但数据库有数据 | 检查评价 `status`：被后台隐藏的评价前台不展示 |
| 管理端改了后端地址不生效 | 地址存于浏览器 `localStorage`，换浏览器需重新配置 |
| 打包失败提示 appid 相关 | manifest.json 的 `appid` 不能为空，需登录 HBuilderX 后获取 |
| 退出登录后接口返回 401「登录状态已失效」 | 正常行为：令牌已被服务端吊销。重新登录即可拿到新令牌（见 2.3.2） |
| 旧令牌仍能访问接口 | 先确认 `JWT_REVOCATION_ENABLED` 未被设为 false；再确认 Redis 在运行（Redis 故障时会降级放行并打告警）；最后确认请求用的是不是**同一枚**令牌 —— 吊销只作用于被登出的那一枚 |

## 6. 答辩演示建议流程（约 5 分钟）

1. **APP 端购物闭环**：首页浏览 → 搜索 → 详情页加购 → 购物车结算 → 下单 → 模拟支付（1.5 分钟）
2. **管理端介入**：后台登录 → 总览数据 → 订单发货 → 用户下单商品库存/销量变化（1 分钟）
3. **回到 APP**：确认收货 → 发表评价 → 详情页查看评分与评价列表（1 分钟）
4. **管理端治理**：评价管理隐藏违规评价 → APP 端即时不可见 → 恢复（1 分钟）
5. **技术点展示**：Redis 缓存前后耗时对比、降级验证、Knife4j 接口文档（0.5 分钟）
