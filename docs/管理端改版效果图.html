线上书店 · 管理端改版方案 v1.0

从「功能清单」到「运营工作台」

依据三张电商运营后台参考图，对照 bookstore-admin 现有实现（Layout / 首页总览 / 订单管理）与后端已有接口能力， 提炼可复用的设计范式，给出本期可落地的改版方向与两张页面效果图。标注针编号与下方改动清单一一对应。

现成接口可支撑 需后端补字段 可选 / 本期不做

已落地：主色取参考图的紫 #6C4DF2；令牌 / 侧栏分组 / 工作台 / 订单页四批改动完成， OverviewVO.statusCounts 与订单日期区间两个后端字段已补齐。效果图与实际实现的差异以代码为准。

一、三张参考图的拆解

三张图分别覆盖「工作台 / 列表管理 / 数据分析」三类典型后台页面，共性比差异更值得复用。

图 1 / 3 —— 工作台

一屏交代「规模 + 分布 + 待办」

信息架构
KPI 卡（5 张）→ 订单状态条 → 趋势折线 + 状态环图 → 平台占比 / 热销 / 待办三栏。自上而下：概览 → 结构 → 明细。
导航布局
左侧 224px 固定栏：品牌块 + 3 组菜单（日常运营 / 经营分析 / 系统），每项 34px 高、图标 16px；当前项浅色药丸高亮。
数据展示
KPI 主数字 26px 加粗、副文本 11px 说明口径；增减用彩色箭头；状态用「圆点 + 文字 + 计数」胶囊而非纯色标签。
交互方式
状态胶囊本身即入口（点击直达已筛选列表）；图表只在卡内切换维度，不跳页；待办清单每行可点。
视觉风格
白卡片 + 14px 圆角 + 极浅描边，页面底色 #F6F7F9；主色紫，仅用于主按钮与数字强调；每张卡右上角有一枚低透明度色晕。

图 2 / 3 —— 订单列表

「汇总 → 筛选 → 表格」三段式

信息架构
页面标题副标题 → 4 格汇总条（随筛选变化）→ 筛选卡 → 表格卡（标题带条数）。
导航布局
顶栏固定：全局搜索（订单号 / 联系人 / 电话 / 商品）+ 快捷新增 + 头像；列表页无二次侧栏。
数据展示
10 列宽表：订单号两行（号 + 时间）、平台用浅色小标签、商品带缩略图、金额右对齐；状态为 21px 高胶囊带圆点。
交互方式
日期区间旁挂「今日 / 近 7 天 / 近 30 天 / 近 6 个月 / 全部」快捷片；批量操作条仅在勾选后出现；行内「详情」文字链 + 「发货」实心小按钮，主次分明。
视觉风格
去掉竖线，只留 1px 横细线；表头 11px 灰字浅底；行高 56px，信息密度与扫读性兼顾。

图 3 / 3 —— 数据统计

先定区间与粒度，再出结论

信息架构
区间控件 → 5 张 KPI → 状态 100% 堆叠条 → 趋势图 → 平台维度 / 每日明细。
导航布局
无侧栏切换，同一页面内用「快捷区间 + 按天 / 按周 / 按月」分段控件完成全部切片。
数据展示
KPI 副文本给出派生指标（客单价、退款率、占比）；状态用一条通栏堆叠条 + 图例同时给「数量 / 占比」，比饼图更省空间。
交互方式
改动区间后必须显式「应用」，右侧回显「当前统计区间」，避免误读；图表右上角用分段控件切换指标。
视觉风格
图表只用主色一个色相（同色系柱状），网格线极浅，去掉图例与边框，靠留白分隔。

二、现有管理端的差距

对照对象：src/layout/index.vue、src/views/dashboard/index.vue、src/views/order/index.vue。
当前全局仅有 .app-card（8px 圆角 / 灰阴影）一个容器样式，主色沿用 Element Plus 默认蓝（#409eff），图表却用 #C8362F 红 —— 品牌色与功能色未收敛。

维度现状（bookstore-admin）参考图做法结论
导航11 项平铺菜单，无分组、无计数角标、不可折叠；顶栏只放标题 + 后端地址 + 退出3 组菜单 + 待处理角标；顶栏承担搜索与账户入口是「目录」，不是「待办」
首屏信息4 张纯文字数字卡（无图标、无对比、无口径以外的预警）5 张卡，图标色块 + 主数字 + 脚注，异常数字带红点看不出「今天有没有事要处理」
数据层级总览 → 一张折线 → 一张柱图 → 快捷操作，单列纵向堆叠，需滚动 2–3 屏KPI → 状态分布 → 趋势 + 环图 → 三栏清单，一屏闭环页面很长但信息很薄
状态可见性无任何订单状态分布；待发货只体现在一个按钮文案里状态条（带计数）+ 环图 + 待办清单，三处互相印证库存 / 超时 / 待发货靠人事后记忆
列表效率订单页只有「订单号 + 状态」两个筛选；表格 7 列全框线、状态用 el-tag 色块；行内操作是两个文字链关键词 + 状态 + 区间 + 快捷时间片；去竖线、主列两行、状态胶囊、主次按钮筛选维度太少，可扫读性弱
视觉系统默认蓝 + 红图表 + 8px 圆角，三套语言混用；无设计令牌单一主色 + 语义状态色阶；统一圆角与描边；数字等宽缺一份可执行的令牌表

三、六个优化方向

按「改动成本 × 收益」排序。P0 全部可在现有接口上完成；P1 需后端补 1–2 个字段；P2 本期不做。

  1. 01导航从「目录」变「队列」P0

    11 项平铺收成 4 组（概览 / 运营 / 商品 / 用户与系统），订单、评价、到货提醒挂计数角标，支持折叠成 64px 图标栏。菜单文案全部保持不变。

    角标：订单待发货 / 到货提醒（现成接口）评价待处理需补字段
  2. 02KPI 带承担「规模 + 异常」P0

    5 张卡：在售图书、注册用户、有效订单、累计销售额、待发货。图标色块区分维度，脚注写清口径（如「不含待支付与已取消」），异常值用红点 + 红字。

    数据：OverviewVO 八个字段全覆盖
  3. 03状态分布做成可点入口P1

    工作台一条状态胶囊（圆点 + 名称 + 计数），点击直达 /order?status=x；同时供订单页的快筛复用，替代单一下拉。

    需补：OverviewVO.statusCounts（一条 GROUP BY）
  4. 04把「提示」升级为「待办清单」P0

    库存不足的 el-alert + 快捷按钮合并为结构化清单：待发货 / 库存不足 / 超时未支付 / 到货提醒，每行带计数与跳转，替代底部「快捷操作」卡。

    待发货、库存不足、到货提醒现成超时未支付需补
  5. 05列表页补全筛选维度与汇总P0

    订单页加汇总条（命中单数 / 当前页合计）+ 快捷时间片 + 状态胶囊；表格去竖线、主列两行、金额右对齐等宽数字、行内「详情」文字链 + 「发货」实心小按钮。

    日期区间需补 createTimeStart/End手机号搜索需补
  6. 06建立视觉令牌，一次性收敛颜色P0

    主色收敛为参考后台的紫 #6C4DF2（管理端不再与商城红混用），状态色做成语义色阶；Element Plus 的 light-3…light-9 / dark-2 必须给全，否则标签、开关、滑块会残留默认蓝。

    纯前端改动见第五节令牌表

四、效果图与标注清单

标注针为紫色序号，与页面下方的改动表逐条对应。关于配色的一处取舍：参考图用低饱和紫作为唯一主色，视觉最稳；本方案沿用这套紫 #6C4DF2，把品牌红彻底留给 APP / 商城的「价格」。为避免紫色被滥用，紫色只出现在主按钮、选中态、关键数字三处，卡片与底图保持中性，状态色则独立成阶（琥珀 / 蓝 / 绿 / 灰）。

六、落地风险与验证方式

  • 既有端到端断言的选择器契约。tools/verify_admin_ui.cjs（27 项）依赖 .layout-menu、.app-header .el-button（按文案点击「新增轮播图」）、.login-box input 与表格行数。分组菜单必须在 .layout-menu 容器内用 el-menu-item-group 实现；页头按钮必须仍在 .app-header 内。菜单文案（轮播图管理 / 书单管理 / 到货提醒）不得改写。
  • Element Plus 派生色。只改 --el-color-primary 时，标签、开关、滑块会用默认蓝计算 light-* → 蓝色残留。按上表给全 3/5/7/8/9 与 dark-2。
  • 新增 statusCounts 与缓存无关。它是订单聚合，不得挂到 category / book 缓存上；若后续加了 @Cacheable，订单状态变更必须同时清该缓存，否则数字会静默停在旧值。
  • 单测联动。src/api/__tests__/admin-endpoints.spec.js（35 项）对 overview 字段做了断言，新增字段需同步 mock 与断言，否则扩展字段时会先红后绿。
  • 不引入新依赖。图标沿用 @element-plus/icons-vue（已全量注册）；热销排行改为 CSS 进度条后，工作台仍保留 ECharts 仅用于趋势图，不新增图表库。
  • 验证口径。改完后跑 npm run build + python tools/run_all_checks.py --reuse-server --with-unit --with-admin --with-frontend --with-web --with-admin-ui，基线为 16 项全通过 / 1084 通过 / 1 已知预期失败；新增断言应累加而非替换。

本文件为设计方案与效果图，不含对 bookstore-admin 的任何代码改动。确认方向后再进入开发，届时按「令牌 → 布局 → 工作台 → 订单页 → 回归」的顺序分批提交。
