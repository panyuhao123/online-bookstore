## 1. 引言

### 1.1 编写目的

本文档定义"线上书店 APP"的功能需求、非功能需求与约束条件，作为后续设计、实现、测试与验收的依据，同时作为毕业论文"需求分析"章节的素材。

### 1.2 背景

传统线下书店受营业时间与地域限制，图书查询、比价与购买效率低。本项目实现一个移动端图书售卖系统：用户在手机上完成"浏览—搜索—加购—下单—支付—收货—评价"的完整购物闭环，商家通过 Web 后台维护商品与订单。

### 1.3 术语与定义

| 术语 | 定义 |
| --- | --- |
| 用户端（APP） | 面向消费者的移动端应用，uni-app 打包为 Android APK |
| 管理端（Web） | 面向商家的后台系统，浏览器访问 |
| 模拟支付 | 不对接真实支付渠道，点击支付后由系统直接改写订单状态并写入支付时间 |
| 逻辑删除 | 通过状态字段标记失效，数据不从库中物理删除 |
| 地址快照 | 下单瞬间把收货地址冗余进订单，避免用户改地址后历史订单被污染 |
| 隐藏评价 | 后台对违规评价的处理方式：前台不可见且不计入平均分，数据保留可追溯 |

## 2. 系统概述

### 2.1 系统定位与形态

系统由三部分构成，通过 HTTP + JSON 交互：

```
┌──────────────────┐        ┌──────────────────┐
│  用户端 APP       │        │  Web 管理后台     │
│  uni-app(Vue3)   │        │  Vue3 + Element+  │
│  Android APK     │        │  浏览器访问        │
└────────┬─────────┘        └────────┬─────────┘
         │  /api/**                  │  /api/admin/**
         └───────────┬───────────────┘
                     ▼
        ┌────────────────────────────┐
        │  后端 bookstore-server      │
        │  SpringBoot3 + MyBatis-Plus │
        └───────┬─────────┬──────────┘
                ▼         ▼
             MySQL 8   Redis / MinIO
```

### 2.2 用户角色

| 角色 | 载体 | 主要职责 |
| --- | --- | --- |
| 消费者 | APP | 注册登录、浏览搜索图书、管理购物车与地址、下单支付、确认收货、发表评价 |
| 管理员 | Web | 维护分类与图书、处理订单发货、管理用户与评价、查看经营统计与操作日志 |

### 2.3 总体业务流程

```
浏览/搜索图书 ──▶ 加入购物车 ──▶ 勾选结算 ──▶ 选择收货地址
                                                 │
                                                 ▼
                                            生成订单（待支付）
                                                 │
                                    ┌────────────┼────────────┐
                                    ▼                         ▼
                              模拟支付（已支付）          取消 / 超时关闭（已取消）
                                    │
                                    ▼
                          后台发货（已发货）──▶ 用户确认收货（已完成）──▶ 发表评价
```

## 3. 功能需求

### 3.1 APP 用户端

| 编号 | 需求点 | 说明 |
| --- | --- | --- |
| F-A01 | 注册 | 手机号 + 密码注册，手机号唯一；密码以 BCrypt 密文存储（早期为 MD5(明文 + 8 位随机盐)，已按安全加固要求升级，旧密文在登录时自动重写） |
| F-A02 | 登录 | 手机号 + 密码 + 图形验证码登录，成功后返回 JWT；令牌过期或失效返回 401，APP 清空令牌并跳登录页；同一账号连续失败达阈值即临时锁定，锁定期内即使密码正确也拒绝（防在线暴力破解） |
| F-A03 | 首页 | 楼层式布局：运营轮播 → 功能宫格 → 图书楼层（新书 / 热销 / 低价），各楼层数据独立加载，单楼层失败不影响整页 |
| F-A04 | 搜索 | 顶部搜索框支持关键词检索，按"书名 OR 作者"模糊匹配；空结果给出引导文案 |
| F-A05 | 列表排序 | 支持综合、销量、价格升、价格降四种排序，非法排序值静默回落为默认 |
| F-A06 | 分类浏览 | 一级分类列表；分类下有书时不可删除（后台约束） |
| F-A07 | 图书详情 | 展示封面、书名、作者、出版社、价格、库存、简介、评分与评价摘要；支持立即购买与加入购物车 |
| F-A08 | 购物车 | 增、改数量、勾选/取消、删除、批量删除；同一书重复加入累加数量；合计与件数前端实时计算 |
| F-A09 | 未登录购物车 | 未登录时购物车存本机，登录后自动合并到服务端并清理本地数据 |
| F-A10 | 收货地址 | 省/市/区 + 详细地址，支持新增、编辑、删除、设为默认 |
| F-A11 | 下单 | 以购物车已勾选条目为来源，校验库存后生成订单，扣减库存，写入地址快照 |
| F-A12 | 模拟支付 | 点击支付将订单置为已支付并写入支付时间；提供支付回调接口用于模拟第三方通知 |
| F-A13 | 订单管理 | 分页列表（按状态筛选）、订单详情、取消订单、确认收货 |
| F-A14 | 评价 | 已完成订单可发表评分与文字评价，支持匿名；同一订单同一本书仅可评价一次 |
| F-A15 | 我的 | 个人信息、订单入口、地址入口、退出登录（服务端吊销令牌，退出后原令牌立即失效）、服务器地址配置 |
| F-A16 | 服务器地址 | 支持自动探测局域网后端地址，也支持手动指定，便于真机联调 |

### 3.2 Web 管理端

| 编号 | 需求点 | 说明 |
| --- | --- | --- |
| F-B01 | 管理员登录 | 账号密码登录，令牌存储于本地；未登录路由拦截 |
| F-B02 | 首页总览 | 核心经营指标卡片（用户数、订单数、销售额等）与销售趋势 |
| F-B03 | 图书管理 | 分页查询、新增、编辑、上下架、删除；书名+作者判重；已产生订单的图书只能下架不能删除；支持封面上传 |
| F-B04 | 分类管理 | 分类增删改查，分类下有图书时禁止删除 |
| F-B05 | 订单管理 | 订单分页与详情、发货操作、超时未支付订单批量关闭 |
| F-B06 | 用户管理 | 用户分页查询、启用/禁用 |
| F-B07 | 评价管理 | 评价分页查询（按图书关键词、星级、状态筛选）、隐藏/恢复、删除；隐藏优先于删除 |
| F-B08 | 操作日志 | 关键管理操作留痕，可按模块检索 |
| F-B09 | 系统设置 | 运行时切换后端地址，便于多环境调试 |

### 3.3 公共约束

- 所有接口统一返回 `{code, message, data, timestamp, requestId}`，HTTP 状态码恒为 200，业务成败仅看 `code`。
- 鉴权：`Authorization: Bearer <token>`；`/api/admin/**` 强制 ADMIN 角色。
- 免登录接口仅包括：`/api/book/**`、`/api/category/**`、注册/登录/登出、管理员登录、健康检查、`/files/**`。

## 4. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 图书详情等热点读接口引入 Redis 缓存（实测详情接口约降低 36% 耗时）；价格排序追加 id 次要排序键以保证分页稳定 |
| 安全 | 密码以 BCrypt 慢哈希存储（历史 MD5 密文登录时透明升级）；JWT 无状态鉴权 + 方法级角色校验；令牌有效期 24 小时（生产 12 小时）且退出登录在服务端吊销令牌；越权访问返回 403；用户只能操作自己的地址、订单与评价；登录失败达阈值临时锁定账号（APP 端与管理端同一策略，不存在的账号同样计数以防账号枚举） |
| 可靠性 | Redis 不可用时通过熔断与降级策略继续提供服务，不阻断主流程 |
| 一致性 | 下单防超卖使用条件更新 `UPDATE book SET stock=stock-n WHERE id=? AND stock>=n`；订单明细冗余书名/单价/封面 |
| 易用性 | 遵循统一 UI 规范（品牌色 #C8362F，触控区 ≥88rpx，正文 ≥26rpx）；统一空态、加载态与错误提示 |
| 兼容性 | APP 目标平台 Android；Android 9+ 需开启明文流量；真机联调使用局域网 IP |
| 可维护性 | 分层架构（Controller / Service / Mapper）；统一异常与日志；接口文档由 Knife4j 自动生成 |

## 5. 假设、依赖与范围外事项

### 5.1 假设与依赖

1. 支付环节为**模拟支付**，不接入支付宝/微信真实渠道，重点验证订单状态机与回调处理逻辑。
2. 演示环境的 MySQL、Redis、MinIO 需在本机启动；Redis 与 MinIO 未设为开机自启。
3. 真机联调依赖电脑局域网 IP，IP 可能变化，APP 内置自动探测与手动配置双通道。

### 5.2 明确不在范围内

收藏、优惠券、积分、消息推送、图书在线阅读、售后退款、物流轨迹对接、多商户。
